# Бот-помощник студента (проект)

Telegram-бот: сроки из календаря LMS, отправка работы преподавателю в элжур, баллы и калькулятор.
Часть «сисадмин»: Docker, шифрование секретов, healthcheck, бэкапы с проверкой восстановления.

## Что проверено, а что нет
- Проверено тестами (`python tests/test_core.py`): разбор календаря, калькулятор, бэкап с проверкой.
- **Не проверено на живых сервисах:** `app/eljur.py` (места с `CHECK`) и сам бот aiogram.
  Первая отправка в элжур — только себе или одногруппнику, не преподавателю.
- Вход в элжур не автоматизирован: бот берёт cookie уже открытой сессии (`/setcookie`),
  она со временем истекает. Пароли бот не хранит.
- Пороги оценок (`app/calculator.py`) и пересчёт в 12-балльную шкалу — предположения, сверьте с правилами колледжа.

## Запуск на сервере (Linux + Docker)
```
cp .env.example .env
python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"   # вставить в SECRET_KEY
nano .env                      # BOT_TOKEN от @BotFather, ADMIN_ID
docker compose up -d --build
docker compose ps              # статус healthy = бот жив
docker compose logs -f bot
```

## Бэкапы (cron на хосте)
```
crontab -e
0 3 * * * /путь/к/проекту/scripts/backup.sh
```
Копия делается через API SQLite, проверяется (`integrity_check`, наличие таблиц), хранятся 7 последних,
результат приходит админу в Telegram. Восстановление: остановить бота, положить нужный файл из `data/backups/`
как `data/bot.db`, запустить.

## Безопасность
- Ссылка календаря и cookie элжура хранятся зашифрованными (Fernet); ключ только в `.env`, файл `.env` не коммитить.
- Контейнер работает не от root, наружу порты не открыты (бот сам ходит в Telegram).
- На сервере: вход по SSH-ключам, `ufw allow 22/tcp` и всё остальное закрыто, `unattended-upgrades`.
